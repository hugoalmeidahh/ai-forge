# Write a useful document

Identify audience, decision/task, source material and delivery format. Read existing documentation and preserve its location/style when they work. Distinguish Markdown content work from producing an actual office/PDF artifact.

1. Extract known facts, evidence, assumptions and gaps. Ask only questions that materially change the document; progress independent sections while waiting.
2. Build an outline around the reader's decision. State the recommendation/outcome early, then context, evidence, alternatives, trade-offs and next actions where relevant.
3. Draft with stable terminology and traceable references. Never invent metrics, quotations, approvals or stakeholder positions. Redact private inputs when creating public documentation.
4. Check internal consistency, links, scope and whether examples agree with the actual API/code. Reuse one source of truth instead of duplicating business rules across sections.
5. Test the reader's path: can they identify purpose, prerequisites, action and success without this chat? Use a bounded independent read when available and authorized; otherwise perform a structured self-review and state its limits.

Deliver the document, material unresolved questions and verification performed. For office/PDF output, use an installed capable artifact tool or the appropriate `ai-forge-artifacts-*` skill; prose alone is not a generated file.
