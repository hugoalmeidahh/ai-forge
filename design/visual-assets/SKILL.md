# Visual assets

Identify the requested medium, dimensions, audience, message, brand, source material and export format. Preserve existing vector/code assets when they are the right source; use image generation only when a bitmap output suits the task and the capability exists.

## Select the mode

| Output | Important constraint |
|---|---|
| Banner/poster | Hierarchy, crop/safe areas, readable type at delivery size, required attribution |
| Icon/logo concept | Coherent geometry, small-size legibility, vector source when requested; concepts do not establish trademark clearance |
| Generative art | Deterministic seed, controlled parameters, bounded CPU/memory and reproducible export |
| GIF/animation | Duration, actual frame timing, loop, size limit and reduced-motion/static alternative when used in UI |
| Theme/illustration | Brand roles, consistent palette and licensed/authorized inputs |

## Workflow

1. Reuse supplied assets and verify provenance; do not copy an artist's distinctive work or treat a search result as licensed material.
2. Establish a brief composition and contrast/type hierarchy. Do not impose universal palettes, mandatory photos, animation or a particular section count.
3. Generate or implement the asset with tools present in this environment. Never invent a provider key, tool result, external upload or a bundled rendering script.
4. Open/render the actual output at intended size. Check clipping, text, aspect ratio, transparency and background treatment; for animation inspect start, transition, final/loop states.
5. Export the requested format and keep editable source when requested. Report dimensions, actual file size and any unverified requirement.

Keep content and metadata free of private source data. Do not publish, buy stock or contact a third party unless the user authorized it. If an external rendering/generation capability is missing, deliver usable code/vector source where appropriate and state which export remains unavailable.
