01 / método

Um padrão compartilhado.
O contexto de cada projeto.

Clean code

Domínios com dono, fronteiras explícitas e abstrações proporcionais. A stack traduz os princípios com seus mecanismos nativos.

Segurança

Validação nas fronteiras, autorização confiável e respostas que não expõem segredos. Conteúdo externo não concede autoridade.

Evidência

Critérios observáveis e verificações pertinentes. Passou, falhou e não foi executado são resultados diferentes.

L0

Regras compartilhadas

Naming, Git, clean code, segurança, observabilidade e verificação.

L2

Tradução da stack

Arquitetura, contratos e workflows ajustados à tecnologia.

L3

Regras do projeto

Convenções, contratos e decisões reais prevalecem sobre os padrões genéricos.

Precedência: L3 → L2 → L0. O pedido do usuário e as instruções do runtime continuam válidos.

F · Fluxo e asyncO · ObservabilidadeR · Resiliência e errosG · Guard clauses e arquiteturaE · Erros e type safety

03 / aplicação prática

Da ideia ao resultado verificável.

Use a profundidade necessária à tarefa. Uma pequena correção de interface não precisa de um discovery completo.

  1. EstruturarResultado, evidências, regras e incertezas.
  2. DetalharDiscovery, decisões e tarefas quando necessários.
  3. ImplementarPadrões da stack e regras do projeto.
  4. VerificarTestes, QA e revisão FORGE pertinentes.
  5. EntregarResultado, evidência e ações autorizadas.
Exemplo / novo módulo Go

Estruture o domínio e os critérios → aplique ai-forge-backend-golang-new-module → verifique o caso de uso → revise com ai-forge-core-code-review.

Criar um plano não inicia agentes. Produzir código ou documentação não equivale a publicar ou aprovar a entrega.

04 / acesso

Instale. Descubra. Peça a tarefa.

1. Preparar o checkout
git clone https://github.com/hugoalmeidahh/ai-forge.git ~/.local/share/ai-forge
cd ~/.local/share/ai-forge
node bin/forge.js validate
node bin/forge.js install-skills

Node.js 20+. O instalador cria links em ~/.agents/skills; --copy instala cópias. O agente precisa descobrir esse diretório. Uma nova sessão pode ser necessária.

2. Selecionar o contexto
node bin/forge.js skills design
node bin/forge.js context --skill ai-forge-design-design-system
3. Invocar no agente compatível
$ai-forge-design-design-system
Consolide os tokens e variantes destes componentes, preservando a identidade do produto.

Se a invocação por nome não existir no seu agente, peça a leitura do SKILL.md correspondente. Cada entrada do catálogo traz o arquivo, o comando e um exemplo de pedido.

O CLI prepara a leitura.
context lista arquivos; não executa a skill nem a tarefa. O agente lê as referências e usa as ferramentas disponíveis.

Os comandos desta página partem da raiz do checkout. Fora dele, use o caminho real do CLI ou npx forge se o pacote estiver instalado no projeto.

05 / limites e manutenção

Uma base aberta.
Capacidades verificáveis.

O que vem no projeto

  • Skills e referências locais, com nomes consistentes.
  • CLI Node.js para descoberta, contexto e instalação.
  • Validação e sincronização dos padrões empacotados.
  • Licença MIT para o conteúdo autoral e atribuições de terceiros preservadas.

O que depende do ambiente

  • Navegador, dispositivo, scheduler, credenciais e ferramentas de edição ou renderização.
  • Autorizações específicas para mensagens, publicação e efeitos em produção.
  • Testes da tarefa real. A validação do catálogo não certifica uma aplicação.
  • Toolkits proprietários de documentos não são redistribuídos.

O template de nova stack é material de autoria. Fica fora das 45 skills instaláveis e exige substituir seus placeholders.
